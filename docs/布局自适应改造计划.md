## 一、背景与初衷

历史上为内容布局与重叠问题打过多轮补丁：

- `4afbc0c` feat: improve axis label rotate
- `0d88cee` fix(pie): 优化饼图标签避让算法，采用对称均匀分布
- `f02c2cb` wip(pie): add collision-avoidance for outside labels and auto-legend support
- `e965b5f` fix: 适配 lievisual 0.1 API 并修复 SVG 输出布局问题

每一轮都在解决单个症状。本次改造的目标是从根上换掉它们共同的隐含前提：**画布是不可变的刚性容器**。

参照对象是 `../liemermaid`（布局产出自然尺寸 → `fit_scene` 贴合内容）。但图表与流程图的方向相反，不能照搬，详见 §三。

### 2.3 所有图形都是流体（撑满容器），无自然尺寸

| 元素 | 尺寸来源 |
|---|---|
| Pie | center/radius 按 `bounds` 百分比（`builder/pie.rs:42-55`）；标签 clamp 到 `canvas_{w,h}-8`，放不下就压缩间距（`builder/pie.rs:266-340`） |
| Table | `cell_h = bounds.h/(rows+1)`，行越多字越挤（`builder/table.rs:46-47`） |
| 数值轴 | 刻度数硬编码 5（`axis_renderer/mod.rs:83,89`），与画布无关 |
| 类别轴 | 旋转 + 抽稀塞进槽宽（`collision.rs:134-171`） |
| 图例 | 单行不换行，`start_x=(width-total)/2` 可为负 → 溢出裁剪（`decorator/legend.rs:116-117`） |

### 2.4 根因三连

**根因 1：测量双轨。** 注释声称与 renderer 共用同一套旋转决策：

```99:103:src/pipeline/grid_planner.rs
    /// 与 `CartesianAxisRenderer` 共用同一套旋转决策：
    /// - X 轴标签横向放不下时自动旋转（45°/90°），按旋转后的投影高度预留底部空间
    /// - Y 轴标签按宽度预留左侧/右侧空间
    ///
    /// 文本尺寸使用启发式估算（见 `axis_label::estimate_text_size`），无需字体引擎。
```

实际 planner 用启发式估算（CJK 1.0em / 半角 0.55em，`axis_label.rs:15-25`），renderer 用 parley 真实测量（`cartesian.rs:79-93`）。两者 `max_w` 不同 → 旋转角决策不一致 → 预留边距对不上。
数值轴在 planner 里更是用占位串 `"1234.5"` 顶替真实刻度（`grid_planner.rs:118,140`）。

**根因 2：单向数据流，没有"需求 → 画布"回路。**
`estimate_header_height`（`:64`）→ `GridPlanner`（`:67`）→ 轴（`:113`）→ 系列 → 装饰，尺寸只往下传。

**根因 3：冲突手段只有退化，且无统一代价排序。**
按信息损失排序应为：扩画布（0）> 旋转 45° > 旋转 90° > 抽稀（丢标签）> 压缩（重叠）。现有 5 处（轴/饼图/表格/图例/grid）各自为政，凭手感选了偏狠的那档。

### 2.5 附带的尺寸语义问题

- **Pie radius 基准不一致**：api 层按 `min(width,height)*0.5` 折百分比（`api/chart.rs:952-963`），builder 按 `min(bounds.w,bounds.h)*0.5` 还原（`builder/pie.rs:53-55`）。多 subplot 时饼图偏大。
- **Grid 百分比提前固化**：`Position::Percent` 在 api 层就折成像素（`api/chart.rs:656-659`），于是 planner 里 `grid.left.is_some()` 分支会再叠 `LABEL_LEFT_PADDING=50`（`grid_planner.rs:294-303`），`Grid::default()`（10%）也吃到；且画布变大后固化像素不跟随。
- **整画布背景矩形**（`chart_pipeline.rs:93-100`）使 scene bbox ≡ 画布，任何 bbox 计算都被污染。

## 三、参照 liemermaid：可借鉴什么，不能照搬什么

liemermaid 的做法（`liemermaid/src/builder/mod.rs:33-38`）：

```33:38:../liemermaid/src/builder/mod.rs
    let sg = materialize::run(&gg, &style);
    let mut scene = paint::run(&sg);
    // 画布贴合内容（官方 mermaid 语义：`config` 是上限而非固定画布）
    scene.background = config.background;
    fit_scene(&mut scene, fit_options(config));
```

`lievisual::fit::fit_scene`（`fit.rs:429-491`）用 `scene_bounds` 算 bbox（计入 stroke 半宽与节点 transform），`scale=min(avail/w, avail/h)`，`upscale=false` 时 clamp 到 ≤1，写回 `scene.width/height = content*scale + 2*margin`，并把默认层节点包进 `Group(translate∘scale)`。

**可借鉴的本质**：`measure → layout` 的阶段分离，以及"尺寸作为布局产出而非输入"。

**不能照搬 `fit_scene` 的原因**：

1. mermaid 是单向的（节点尺寸不依赖画布）→ 末端一次 fit 足够；图表是**双向耦合**（绘图区大小决定刻度密度/旋转决策，标签需求又反向要求绘图区外的空间）→ 必须是约束求解，而非事后缩放。
2. 直接对现有 Scene 调 `fit_scene` 无效且有害：背景矩形使 bbox≡画布（scale 恒为 1）；即便去掉，流体布局下 bbox 恒≈画布内框（被压缩的长标签量出来"刚好在画布内"）；且 `Group+transform` 会破坏像素语义与现有断言。

**结论**：把 liemermaid 的思想翻译成图表版——**把"尺寸"从输入常量变成布局的求解变量**，组件分两类：

| 类型 | 成员 | 尺寸由谁定 |
|---|---|---|
| 固定型（rigid） | 所有文本、图例项、轴标签、表头、仪表盘刻度 | 内容测量决定，不可压缩 |
| 弹性型（flex） | 绘图区、柱宽、饼半径、折线、网格间距 | 吃掉剩余空间 |

## 四、目标与非目标

**目标**

1. 消除测量双轨，planner 与 renderer 使用同一份真实测量。
2. 建立"需求上报 → 分配 → 收敛"的布局回路，空间不足时可选择长大画布（信息零损失）而非退化。
3. 统一的冲突代价模型，替代各处的临时 clamp。
4. 默认行为（`Fixed` 模式、800×600 输出尺寸）保持不变，向后兼容。

**非目标**

- 不做默认的整体缩放（图表通常要塞进固定版位，缩字号不符合 ECharts 语义）。
- 不引入新的外部依赖（复用已锁定的 `lievisual =0.2.0-beta.2`）。
- 不改动 `ChartSpec` / `ChartOption` 的公开字段语义。

## 五、分期计划

### P0 — 阶段解耦与测量统一

**目标**：让 `GridPlanner` 在布局前就能拿到真实的轴标签尺寸，消除根因 1。

关键前提（已验证）：`AxisBindingResolver::resolve(&specs)` 只用到 `specs` 的**绑定关系**（`id` / `series_indices` / `x_axis_indices` / `y_axis_indices`），不依赖 `bounds`。因此绑定与轴范围可以提到像素布局之前。

调整后的管线：

```text
1. bind()      series/axis → subplot 绑定关系          （无像素）
2. resolve()   轴范围 min/max                          （无像素）
3. ticks()     生成刻度标签文本                         （无像素）
4. measure()   TextMeasurer 真实测量                    （无像素）
5. plan()      GridPlanner 用实测尺寸决定 subplot bounds（产生像素）
6. materialize → build → decorate
```

改动点：

| # | 文件 | 改动 |
|---|---|---|
| P0.1 | `pipeline/grid_planner.rs` | 抽出 `SubplotBinding`；`bind()` 与 `plan()` 分离，`bind()` 不触碰 bounds |
| P0.2 | `pipeline/chart_pipeline.rs` | 调整阶段顺序：bind → resolve → ticks → measure → plan |
| P0.3 | `pipeline/grid_planner.rs` | `adjust_label_margins` 改用 `TextMeasurer` 实测；数值轴改用真实刻度标签文本，移除 `VALUE_TICK_ESTIMATE` |
| P0.4 | `pipeline/types.rs` | `TextMeasurer` 增加测量缓存（同一文本/样式在 planner 与 renderer 间复用） |
| P0.5 | `pipeline/grid_planner.rs` | `plan()` 改 `&mut self`（需要 `&mut TextMeasurer`），同步更新 6 处测试调用 |

**验收**：`cargo test --workspace` 全绿；`Fixed` 模式下绘图区边界相对基线的变化需逐项记录并解释（见 §七）。

### P3 — 统一冲突调度

`collision.rs` 的 `CollisionResolver` 提升为全局策略：按 `Degrade` 代价排序，可扩画布时优先 `Grow`，`Fixed` 模式才逐级退化。饼图 `distribute_*`、表格行高、图例换行接入同一调度。

> **状态：已完成（2026-09-01）**。本轮落地的是代价排序最核心的一档——**Hug 模式下轴标签冲突优先扩画布（零损失），而非旋转/抽稀**：
> - X 轴：`auto_rotate` 判定需旋转时上报「绘图区宽度需求」（画布加宽到 `n × 标签宽`，槽宽 ≥ 标签宽后下一轮自动恢复水平且不抽稀）；
> - Y 轴 category：标签过多将抽稀（`label_step > 1`）时上报「绘图区高度需求」（画布加高到全部标签可见）；
> - 用户显式 `label_rotate` 不干预（可能是有意排布）。
> 未引入 `Degrade` 枚举类型——代价模型以"`Grow`（扩画布，零损失）> 旋转/抽稀（Fixed 现状）> 压缩（兜底）"的语义固化在需求回路与注释中。饼图 `distribute_*`/图例换行已在 P1 接入需求回路。
